Antes de começar · Visão geral

Como o Git funciona?

Imagine o Git como uma linha do tempo do projeto. Cada desenvolvedor trabalha em sua própria cópia, registra pontos seguros e depois compartilha esses pontos com a equipe.

💻 Arquivos
você edita→📦 Stage
git add→📸 Commit
git commit→☁️ GitHub
git push
Ideia principal: o Git controla versões localmente. O GitHub permite compartilhar essas versões e colaborar pela internet.
Antes de começar · Histórico

Commits formam a história do software

● C1
projeto inicial→● C2
cria login→● C3
corrige validação→● C4
novo layout

Cada círculo representa um commit: um ponto identificado no histórico. Isso permite saber quem alterou, o que mudou e em qual sequência.

git log --oneline
Antes de começar · Branch

Branch = uma linha paralela de trabalho

Uma branch permite desenvolver uma funcionalidade sem alterar diretamente a versão principal.

main       ●────●──────────────●
                \              ↑ merge
feature/login    ●────●────●────┘
                 login em desenvolvimento

main

Representa a linha principal e, normalmente, a versão integrada do projeto.

feature/login

Espaço separado para implementar o login, testar e criar commits sem interromper a main.

Antes de começar · Branch na prática

Crie uma branch para sua tarefa

# veja onde você está
git branch

# crie a branch e já entre nela
git switch -c feature/login

# confirme a branch atual
git branch

O símbolo * indica a branch em que você está trabalhando.

* feature/login
  main
Boa prática didática: uma tarefa ou funcionalidade → uma branch. Exemplos: feature/login, feature/cadastro, fix/validacao-email.

Exemplo: duas branches ao mesmo tempo

                         ┌── ●──●  feature/login (Ana)
main  ●────●─────────────┤

Ecossistema Git · servidores remotos

GitHub não é o único servidor Git

O Git é o sistema de controle de versão. Já serviços como GitHub, GitLab, Bitbucket e Azure Repos hospedam repositórios remotos e adicionam recursos de colaboração.

GitHub

Hospedagem de repositórios Git, colaboração, Pull Requests e automação. Será a plataforma principal dos nossos exemplos.

GitLab

Plataforma de DevSecOps com repositórios Git e recursos integrados de planejamento, CI/CD, segurança e entrega.

Bitbucket

Hospedagem e colaboração Git da Atlassian, com integração forte ao Jira e CI/CD pelo Bitbucket Pipelines.

Azure Repos

Serviço do Azure DevOps para repositórios Git, Pull Requests, revisão de código e políticas de branch.

Importante: os comandos Git continuam praticamente os mesmos. O que muda principalmente é a URL do repositório remoto e os recursos oferecidos pela plataforma.

01 · Conceito

Git não é GitHub

Git

Sistema de controle de versão instalado no computador. Registra o histórico das alterações do projeto.

GitHub

Plataforma online que hospeda repositórios Git e facilita colaboração, revisão e compartilhamento.

Imagem mental: Git é a máquina fotográfica do histórico; GitHub é o álbum online compartilhado.

02 · Preparação

Instale e confira o Git

git --version

Se aparecer uma versão, o Git está disponível. Depois abra Git Bash, Terminal ou terminal integrado da IDE.

Objetivo: antes de criar repositórios, garantir que o computador reconhece o comando git.
03 · Identidade

Configure nome e e-mail

git config --global user.name "Seu Nome"
git config --global user.email "seuemail@exemplo.com"

git config --global --list

Esses dados identificam o autor dos commits. --global aplica a configuração aos seus repositórios no computador.

04 · Projeto local

Crie uma pasta de estudo

mkdir projeto-git
cd projeto-git

No Windows/Git Bash use cd projeto-git. O “a” acima não é necessário — use somente o comando abaixo:

cd projeto-git

Crie dentro dela um arquivo README.md e, se quiser, um index.html.

05 · Inicialização

Transforme a pasta em repositório

git init -b main
projeto-git/+.git/=Repositório Git

O diretório oculto .git guarda metadados e histórico. Não edite essa pasta manualmente.

06 · Diagnóstico

Seu comando mais frequente

git status

Mostra a situação do repositório: arquivos novos, modificados, preparados para commit e branch atual.

Regra de estudo: ficou em dúvida? Rode git status.
07 · Fluxo local

Working → Staging → Commit

Arquivo alterado
Working Directorygit add →Preparado
Staging Areagit commit →Histórico
Repository

O Git permite escolher exatamente quais mudanças entram no próximo “ponto salvo”.

08 · Stage

Prepare arquivos para o commit

git add README.md
# ou todos os arquivos da pasta
git add .

git status

git add não envia nada para a internet. Ele apenas coloca mudanças na área de preparação.

09 · Commit

Crie um ponto no histórico

git commit -m "docs: adiciona README inicial"

Um commit registra as alterações preparadas. Use mensagens curtas que expliquem o que mudou.

Exemplos: feat: adiciona cadastro · fix: corrige validação · docs: atualiza README
10 · Histórico

Veja seus commits

git log --oneline

Cada commit recebe um identificador. O log permite acompanhar a evolução do projeto.

7f31abc docs: adiciona README inicial
11 · GitHub

Crie o repositório remoto

No GitHub, crie um repositório vazio, por exemplo projeto-git. Para este exercício com código local já existente, evite inicializar o remoto com README, licença ou .gitignore.

Git local↔origin↔GitHub
12 · Remote

Conecte local e GitHub

git remote add origin https://github.com/SEU-USUARIO/projeto-git.git
git remote -v

origin é apenas o nome/apelido normalmente usado para o repositório remoto principal.

Se aparecer “remote origin already exists”:
git remote set-url origin NOVA-URL
13 · Primeiro envio

Push para o GitHub

git push -u origin main

push envia commits locais. -u define o vínculo da branch local main com a branch remota; depois, normalmente, basta git push.

14 · Ciclo diário

O fluxo que você repetirá

git status
git add .
git commit -m "feat: descreva a alteração"
git push
Editar→Status→Add→Commit→Push
15 · Atualização

Traga mudanças do remoto

git pull

Antes de começar a trabalhar em um projeto compartilhado, atualize sua branch local. O pull busca e integra alterações do remoto.

16 · Clonar

Quando o projeto já existe no GitHub

git clone https://github.com/USUARIO/REPOSITORIO.git
cd REPOSITORIO

clone cria uma cópia local completa do repositório e já configura o remoto origin.

17 · Branches

Trabalhe sem mexer diretamente na main

git switch -c feature/login
# faça alterações
git add .
git commit -m "feat: cria tela de login"
git push -u origin feature/login
main↗feature/login→Pull Request
18 · Ignorar arquivos

.gitignore evita lixo e segredos

# exemplo
node_modules/
target/
build/
.env
*.log
.idea/

Não versione dependências geradas, builds, configurações locais ou arquivos com segredos. Nunca envie senhas, tokens ou chaves de API.

19 · Inspeção

Comandos que ajudam muito

git diff

Mostra alterações ainda não preparadas.

git branch

Lista branches locais.

git remote -v

Mostra os remotos configurados.

git restore arquivo

Descarta alteração local não preparada.

git restore --staged arquivo

Retira arquivo do stage.

git log --oneline

Mostra histórico compacto.

20 · Desafio final

Prática do início ao fim

  1. Configure nome e e-mail.
  2. Crie projeto-git e um README.
  3. Inicialize Git na branch main.
  4. Faça add + primeiro commit.
  5. Crie repositório vazio no GitHub.
  6. Configure origin e confira com remote -v.
  7. Faça o primeiro push -u origin main.
  8. Crie uma branch, altere o projeto e envie a branch.
Resumo

Mapa mental

CONFIGURAR → git config
CRIAR      → git init
VER        → git status / git diff
PREPARAR   → git add
REGISTRAR  → git commit
CONECTAR   → git remote add origin URL
ENVIAR     → git push
ATUALIZAR  → git pull
COPIAR     → git clone
RAMIFICAR  → git switch -c minha-branch

Domine primeiro este fluxo. Depois avance para merge, pull request, conflitos, rebase, tags e colaboração em equipe.
